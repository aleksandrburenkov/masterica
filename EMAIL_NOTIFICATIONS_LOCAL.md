# Локальная настройка и проверка email-уведомлений

Этот файл описывает, как включить и вручную проверить уведомления администраторов
о новых обращениях на локальной машине. Общая логика и production-настройка
описаны в [`README.md`](README.md#email-уведомления-о-новых-обращениях).

## Что должно работать

После сохранения обращения с сайта сервис `RequestNotificationService` сразу
отправляет HTML-письмо:

- владельцу — на альтернативный email или, если он пуст/некорректен, на email
  пользователя с ролью «Владелец»;
- дополнительным получателям из раздела **Настройки → Рассылка обращений**.

Уведомления создаются для:

- записи на мастер-класс;
- запроса мастер-класса без активных сеансов;
- формы на странице «Контакты»;
- выездной заявки;
- первой заявки на онлайн-курс;
- заказа товара из магазина;
- нижней формы «Оставить заявку» на страницах сайта.

Пользовательский сценарий не меняется: после отправки формы на сайте остаётся
прежнее сообщение об успехе.

## 1. Подготовка приложения

Выполните из корня проекта:

```powershell
composer install
php artisan migrate
php artisan config:clear
```

Если база ещё не заполнена демо-данными:

```powershell
php artisan migrate --seed
```

Демо-владелец для локальной проверки:

```text
Email: owner@korni.local
Пароль: password
```

Владелец должен существовать в таблице `users` с ролью `owner` и корректным email.
Если владельца нет, создайте его через админку или сид.

## 2. Отправка почты

### Текущая настройка: OSPanel + Mail.ru SMTP

В OSPanel выбран режим **«Отправлять почту через удалённый SMTP сервер»**:

```text
SMTP сервер: smtp.mail.ru
Порт: 587
Шифрование: TLS
Пользователь / Email отправителя: aleksandr_burenkov1984@mail.ru
```

Эти же значения уже применены в `.env` проекта:

```env
MAIL_MAILER=smtp
MAIL_SCHEME=null
MAIL_HOST=smtp.mail.ru
MAIL_PORT=587
MAIL_USERNAME="aleksandr_burenkov1984@mail.ru"
MAIL_PASSWORD="<пароль приложения из OSPanel>"
MAIL_FROM_ADDRESS="aleksandr_burenkov1984@mail.ru"
MAIL_FROM_NAME="${APP_NAME}"
```

Пароль хранится только в локальном `.env`, который не должен попадать в Git.
`MAIL_SCHEME=null` означает, что Laravel сам выберет `smtp` для порта 587
(STARTTLS) и `smtps` для порта 465.

После изменения `.env` обязательно выполните:

```powershell
php artisan config:clear
```

Для Mail.ru адрес отправителя `MAIL_FROM_ADDRESS` должен совпадать с ящиком,
для которого создан пароль приложения. Если включена двухфакторная
аутентификация, обычный пароль от почты может не подойти — используйте пароль
приложения Mail.ru.

### Вариант A. Лог-драйвер (без реального письма)

Если нужно проверить только формирование письма, временно верните в `.env`:

```env
MAIL_MAILER=log
```

Затем:

```powershell
php artisan config:clear
```

Письмо не уйдёт в почтовый ящик, а появится в:

```text
storage/logs/laravel.log
```

### Вариант B. Локальный SMTP-перехватчик (Mailpit / MailHog)

Запустите Mailpit или MailHog и укажите в `.env`:

```env
MAIL_MAILER=smtp
MAIL_HOST=127.0.0.1
MAIL_PORT=1025
MAIL_USERNAME=null
MAIL_PASSWORD=null
MAIL_SCHEME=null
MAIL_FROM_ADDRESS="noreply@masterica.local"
MAIL_FROM_NAME="Арт-студия Корни"
```

Затем:

```powershell
php artisan config:clear
```

Письма появятся в веб-интерфейсе перехватчика (у Mailpit обычно
`http://127.0.0.1:8025`). Сам Mailpit/MailHog в проект не входит и запускается
отдельно.

### Вариант C. Другой реальный SMTP

Укажите параметры своего почтового сервера в `MAIL_HOST`, `MAIL_PORT`,
`MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_SCHEME`, `MAIL_FROM_ADDRESS`,
`MAIL_FROM_NAME`, затем выполните:

```powershell
php artisan config:clear
```

### Быстрая проверка SMTP без отправки формы

После настройки `.env` можно отправить тестовое письмо прямо из консоли:

```powershell
php artisan config:clear
php artisan tinker --execute='Illuminate\Support\Facades\Mail::raw("Проверка SMTP Masterica", function ($message) { $message->to("aleksandr_burenkov1984@mail.ru")->subject("Проверка SMTP Masterica"); }); echo "OK";'
```

Если команда завершилась без ошибки и вывела `OK`, проверьте ящик
`aleksandr_burenkov1984@mail.ru` (включая папку «Спам»). Если появилась ошибка
авторизации, проверьте пароль приложения Mail.ru и адрес отправителя.

## 3. Настройте получателей в админке

Откройте `http://masterica/admin` и войдите владельцем.

### Альтернативный email владельца

Перейдите:

```text
Настройки → Настройки студии → Почтовые уведомления о новых обращениях
```

Заполните **Альтернативный email владельца** и сохраните. Правило:

1. Заполнен корректный email — письма владельцу идут на него.
2. Поле пустое — используется email пользователя с ролью «Владелец».
3. В поле сохранён некорректный email — срабатывает тот же fallback на email
   владельца из профиля.

### Дополнительные получатели

Перейдите:

```text
Настройки → Рассылка обращений
```

Нажмите **Добавить получателя**, выберите существующего пользователя (например,
`manager@korni.local`) и сохраните. Письма будут приходить на email из его профиля.
Удаление выполняется кнопкой **Удалить** в строке получателя.

Раздел доступен только владельцу. Менеджер, мастер и клиент получают `403`.

### Подписка при создании пользователя

В карточке пользователя есть переключатель **Получать письма о новых обращениях**.
Если он включён, пользователь автоматически появляется в списке рассылки. При
выключении — удаляется из него.

## 4. Ручные сценарии проверки

Перед проверкой убедитесь, что в админке есть владелец с корректным email. В
текущей локальной конфигурации используется реальный SMTP Mail.ru; при
необходимости временно переключите `MAIL_MAILER` на `log` или локальный
SMTP-перехватчик.

| Сценарий | Где отправить | Что проверить в письме |
| --- | --- | --- |
| Запись на мастер-класс | Страница мастер-класса | Мастер-класс, сеанс, участники, контакты, сумма, ссылка `/admin/bookings/{id}/edit` |
| Нижняя форма сайта | Блок «Оставить заявку» внизу страниц | Тип записи, источник в поле «Источник», ссылка на запись или обращение |
| Запрос мастер-класса | Мастер-класс без активных сеансов | Тип «Запрос мастер-класса», текст запроса, ссылка `/admin/contact-requests/{id}/edit` |
| Форма «Контакты» | Страница «Контакты» | Имя, телефон, email, сообщение, ссылка на обращение |
| Выездной мастер-класс | Страница «Выездные мастер-классы» | Направление, дата, место, расстояние, сумма, ссылка `/admin/outreach-requests/{id}/edit` |
| Заявка на курс | Страница курса, кнопка записи | Курс, пользователь, email, статус, ссылка `/admin/course-enrollments/{id}/edit` |
| Заказ товара | Корзина → оформление заказа | Состав заказа, количество, суммы, доставка, ссылка `/admin/orders/{id}/edit` |

После отправки формы на сайте должно появиться обычное сообщение об успехе, а
письмо — в почтовом ящике получателя (при `MAIL_MAILER=smtp`), в перехватчике
(при Mailpit/MailHog) или в логе (при `MAIL_MAILER=log`).

### Куда смотреть результат

При реальном SMTP проверяйте почтовый ящик владельца и папку «Спам». При
лог-драйвере письмо сохраняется в:

```powershell
Get-Content storage\logs\laravel.log -Tail 200
```

Ищите тему:

```text
Новое обращение:
```

Ошибки отправки и проблемы с получателями сервис пишет с префиксом:

```text
[request-notification]
```

Если писем нет, проверьте, что владелец существует, его email корректен, а
SMTP-авторизация проходит.

### Проверка приоритета альтернативного email

1. Оставьте поле альтернативного email пустым.
2. Отправьте форму.
3. Убедитесь, что получатель — `email` владельца из профиля.
4. Укажите альтернативный email, например `alt-owner@example.com`.
5. Отправьте форму ещё раз.
6. Убедитесь, что новое письмо адресовано `alt-owner@example.com`, а не старому
   адресу владельца.

### Проверка fallback при некорректном альтернативном email

Через админку некорректный email сохранить нельзя — форма покажет ошибку. Чтобы
проверить сам fallback в сервисе, временно запишите некорректное значение в БД:

```powershell
php artisan tinker
```

В Tinker:

```php
App\Support\Settings::set('notifications.alternate_owner_email', 'not-an-email');
```

Затем отправьте форму. Письмо должно уйти на email владельца из профиля, а в лог
попадает предупреждение о некорректном альтернативном адресе. После проверки
очистите поле в админке.

### Проверка списка рассылки

1. Добавьте менеджера в **Настройки → Рассылка обращений**.
2. Отправьте одну форму.
3. Должно уйти два письма: владельцу и менеджеру.
4. Удалите менеджера из списка и отправьте форму снова.
5. Должно уйти только письмо владельцу.

### Проверка прав

Под менеджером откройте:

```text
http://masterica/admin/notification-recipients
```

Ожидается `403`. Под владельцем страница должна открываться.

## 5. Автоматические тесты

Точечно:

```powershell
php artisan test --filter=RequestNotificationsTest
```

Полный набор:

```powershell
php artisan test
```

Тесты проверяют отправку по всем формам, получателей, альтернативный email,
fallback, дубликаты, валидность email, права владельца и отсутствие изменений
в пользовательском сценарии.

## 6. Если письма не приходят

- `MAIL_MAILER=log` — письма не попадают в почту, ищите их только в
  `storage/logs/laravel.log`.
- После изменения `.env` выполните `php artisan config:clear`.
- Убедитесь, что пользователь с ролью «Владелец» существует и его `email`
  проходит валидацию.
- Проверьте, что в списке рассылки нет пользователей с пустым/некорректным email:
  такие адреса пропускаются с предупреждением.
- Если используется SMTP, проверьте хост, порт, логин, пароль и шифрование.
- Смотрите ошибки с префиксом `[request-notification]` в логе приложения.

## 7. Важно

- Уведомления отправляются синхронно, без очереди и воркера.
- Ошибка почтового транспорта не отменяет сохранение заявки и не меняет ответ
  пользователю.
- В production используйте реальный `MAIL_MAILER` и настройте SPF/DKIM/DMARC.
- Не храните реальные пароли почтового ящика в Git: используйте `.env` на сервере.
